This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Kirgo is a custom WordPress theme for an e-commerce activewear brand, built on the [Underscores (`_s`)](https://underscores.me/) starter theme and tightly integrated with WooCommerce. This is a **theme**, not a standalone app — it only runs inside a WordPress install with WooCommerce active.

A detailed reference already exists at `AGENTS.md` in the repo root — read it for directory layout, SASS import order/breakpoints, WooCommerce hook inventory, and the per-page template map. This file covers commands and the architectural points not obvious from a file listing.

## Commands

Node deps use Yarn per `package.json`'s `packageManager` field, but the scripts run fine via `npm run` too.

```sh
npm run watch        # SASS + JS watch/rebuild — use this while developing
npm run dev           # one-time dev build
npm run production    # minified production build (SASS -> style.css, JS -> assets/dist/js/app.js)

composer lint:wpcs    # PHPCS against phpcs.xml.dist (WordPress-Theme ruleset)
composer lint:php     # PHP syntax check via parallel-lint
composer make-pot     # regenerate languages/_s.pot
```

There is no test suite in this repo. `npm run lint:scss` / `npm run lint:js` are referenced in `AGENTS.md`/`README.md` but are **not** currently defined in `package.json`, and eslint/stylelint aren't installed in `node_modules` — don't assume they work; check `package.json` before relying on them.

Build output (`style.css` at repo root, `assets/dist/js/app.js`, `mix-manifest.json`) is generated by Laravel Mix (`webpack.mix.js`) — never hand-edit it. Source lives in `assets/sass/` and `assets/js/app.js`.

## Architecture

**Compiled CSS lives at the repo root.** `style.css` (680KB) is the Mix build output of `assets/sass/app.scss`, not a source file — despite being where WordPress theme headers conventionally live. `webpack.mix.js` sets `processCssUrls: false`, so background-image URLs written in SCSS must be absolute paths (`/wp-content/themes/kirgo-theme/assets/images/...`), not relative ones Mix would normally rewrite.

**Theme override layering for WooCommerce.** Three separate places customize WooCommerce, in increasing order of override power:
- `inc/woocommerce.php` — theme support declarations and hook registration
- `inc/wc-template-functions.php` — large set of function-level template overrides
- `woocommerce/` at repo root — full WooCommerce plugin template overrides (mirrors the plugin's own `templates/` structure; WooCommerce auto-discovers these by path convention, e.g. `woocommerce/single-product/product-image.php`)

`functions.php` (~800 lines) is also a major integration point in its own right — it hosts quantity-button injection, cart/checkout upsell logic, the custom `/wp-json/kirgo/v1/cart-count` REST endpoint, collection-prioritization query filtering, and gettext string overrides. See `AGENTS.md` for the specific hook list and priorities; when adding a new WooCommerce customization, follow its existing pattern (function names prefixed `kirgo_`, hooked at an explicit priority on the relevant `woocommerce_*` action/filter) rather than introducing a new override mechanism.

**Login/registration is a bundled plugin-style module.** `templates/easy-login-woocommerce/` contains `xoo-el-*.php` files — these back a My Account / login-popup flow (XootiX Easy Login for WooCommerce) that's been vendored into the theme rather than left as a plugin dependency.

**Product taxonomy drives upsell logic.** The `product_cat` slugs `core-collection`, `summer-collection`, `classic-collection`, `single-product`, `set-product` are read directly by name in PHP (e.g. cart-page "make it a set" logic, free-shipping-threshold override at `$3000`). Renaming or removing these terms in WP admin will silently break the related-products/upsell code in `functions.php`.

**SASS is mobile-first with `sass-mq`.** Breakpoints and font variables are centralized in `assets/sass/_variables.scss`, which must import first in `app.scss`. Media queries use `@include mq($from: desktop) { ... }` / `$until:` — don't hand-roll `@media` queries when a defined breakpoint applies.

**`assets/js/app.js` is the single JS entry point** — no separate bundles/modules; new JS behavior (nav toggle, WOW.js scroll animations, modal interactions) is added there, compiled to `assets/dist/js/app.js`.

## Conventions

- Text domain: `kirgo`. Custom function prefix: `kirgo_`.
- PHP formatting follows PSR-12-ish style (tabs, brace-on-same-line) as most recently normalized in `functions.php` — match surrounding style, don't reformat whole files incidentally.
- `assets/sass/comman-style.scss` is a known misspelling (should be "common") — intentionally not renamed; the import in `app.scss` matches it.
